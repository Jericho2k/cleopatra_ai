# Deterministic migration order (DB-000).
#
# One filename per line, applied top to bottom after the base schema. Blank
# lines and # comments are ignored. tests/test_schema_pipeline.py applies this
# list to a fresh PostgreSQL and fails if any db/*.sql is missing from it, so a
# new migration cannot be added without choosing where it runs.
#
# The order is not alphabetical, because three real dependencies exist:
#   * full_auto_lifecycle_v1 adds creator_commercial_policies.ppv_payment_window_hours,
#     which operator_ppv_concurrency_v1 then alters.
#   * ppv_delivery_ledger_v1 creates ppv_deliveries, which
#     operator_ppv_concurrency_v1 indexes.
#   * tenant_isolation_v1 discovers every creator-owned table at run time, so it
#     must be last or tables created by later migrations get no RLS policy.
#
# See db/MIGRATIONS.md.

# Durable content-access repair claims: public.content_access_repairs and

content_access_repair_v1.sql

# Owner-only diagnostics: public.message_diagnostics and the

# Assisted provenance that survives a restart or a second replica. Registers

# Production behaviour sprint: fans.conversation_generation (durable

# Conversational Core v2 (session-aware): conversational_session_states and the

# new creator-owned table — before the tenant isolation / least privilege pair.
conversational_session_state_v2.sql

# Always last, and always as a PAIR, in this order.
#
# tenant_isolation_v1 discovers creator-owned tables at run time and gives each
# a FOR ALL policy, so it must run after every table exists.
#
# browser_least_privilege_v1 (SEC-001) then narrows those policies to the
# operations the dashboard actually performs. Running tenant_isolation_v1 ALONE
# silently restores FOR ALL, because it drops every policy on each table it
# discovers before creating its own. Never run one without the other.
tenant_isolation_v1.sql
browser_least_privilege_v1.sql
